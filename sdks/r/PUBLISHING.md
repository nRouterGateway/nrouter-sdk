# Publishing the R package

Two audiences, and they want different things. Do the first for every release;
the second only when the API is stable enough to defend to a human reviewer.

## Always: pass `R CMD check` cleanly

CRAN and R-universe both start here, and so does anyone installing from GitHub.

```bash
cd sdks
R CMD build r
R CMD check nrouter_3.0.0.tar.gz --as-cran
```

**Status: OK is the bar**, with exactly two NOTEs that are not defects and
cannot be cleared locally:

- `checking CRAN incoming feasibility ... NOTE / New submission` — true, and it
  goes away after the first accepted submission.
- `Files 'README.md' or 'NEWS.md' cannot be checked without 'pandoc'` —
  environmental. Install pandoc to clear it; it says nothing about the package.

Anything else is a rejection, not a suggestion. Three that bite here:

- **`License stub is invalid DCF`** — with `License: MIT + file LICENSE`, the
  `LICENSE` file must be exactly two DCF fields (`YEAR:` and
  `COPYRIGHT HOLDER:`), *not* the MIT text. The full text lives in
  `LICENSE.note`.
- **`Undocumented code objects`** — every exported function needs a generated
  `man/*.Rd`. The roxygen comments are the source; regenerate after any change:

  ```bash
  Rscript -e 'roxygen2::roxygenise("r")'
  ```

  Editing `man/*.Rd` by hand is how they drift from the code.

- **`Non-standard file/directory found at top level`** — CRAN inspects the built
  tarball, so a repo-facing file like `PUBLISHING.md` is a finding unless
  `.Rbuildignore` keeps it out of the build. Add new repo-only files there.

`NAMESPACE` is also roxygen-generated. If you add an `@export`, re-run
roxygenise rather than hand-editing.

> **roxygen will not touch a `NAMESPACE` it did not generate.** It looks for the
> literal first line `# Generated by roxygen2: do not edit by hand` and silently
> leaves the file alone without it — no warning, exit 0. That is a quiet way to
> add an exported function, get its `man/*.Rd`, and ship a package where the
> function is not actually exported. If an export is missing after roxygenise,
> check that first line before anything else.

> **Clean up after a check.** `R CMD build` and `R CMD check` leave
> `nrouter_<version>.tar.gz` and `nrouter.Rcheck/` beside the package —
> `.Rcheck/` being a full second copy of the sources. Both are gitignored, so
> they will not be committed, but `scripts/verify-layout.sh` scans the working
> tree and reports phantom failures while they exist. `rm -rf sdks/nrouter.Rcheck
> sdks/nrouter_*.tar.gz` when the check is done.

## R-universe — live public preview

No review queue, and it builds binaries for macOS and Windows. Direct package page:
[https://nrouterai.r-universe.dev/nrouter](https://nrouterai.r-universe.dev/nrouter)

The registry configuration lives at: `https://github.com/nRouterAI/nrouterai.r-universe.dev`

Its `packages.json` maps package `nrouter` to this repository with
`"subdir": "sdks/r"`. Users install with:

```r
install.packages(
  "nrouter",
  repos = c(
    nrouterai = "https://nrouterai.r-universe.dev",
    CRAN = "https://cloud.r-project.org"
  )
)
```

For future releases, update `Version:` in `sdks/r/DESCRIPTION`, commit, and push to `main`. R-universe detects the push and rebuilds automatically.

R-universe rebuilds on every push, so a red `R CMD check` becomes a public red
badge — which is the point.

## Meanwhile: install from GitHub

```r
remotes::install_github("nRouterGateway/nrouter-sdk", subdir = "sdks/r")
```

`subdir` is required because the package lives at `sdks/r` inside the public
repository rather than at its root. Derive it rather than assuming:

```bash
git ls-tree --name-only <public-repo-ref>
```

## CRAN

Only when the API is settled. CRAN is a human review and a maintenance
commitment: a package that breaks under a future R release gets an email with a
deadline, and missing it means archival.

```bash
R CMD check nrouter_3.0.0.tar.gz --as-cran     # must be OK, zero NOTEs
# then submit the tarball at https://cran.r-project.org/submit.html
```

Expect the reviewer to ask about anything that reaches the network. Every
example that would make a real request is wrapped in `\dontrun{}` for exactly
that reason — CRAN runs examples on their machines, without a key.

## Traps

- **Bump `Version:` in `DESCRIPTION`.** CRAN and R-universe both key on it, and
  a resubmission at the same version is rejected.
- **`Suggests: testthat` is right, not `Imports`.** Tests must not be a runtime
  dependency of an installed package.
- **`R CMD check` runs the test suite.** A green `test_dir()` locally is not the
  same signal — check installs the package first, which catches a missing
  `@export` that a source-level run never sees.

## Tagging

```bash
git tag -s sdk-r-v3.0.0 -m "r sdk 3.0.0"
git push origin sdk-r-v3.0.0     # SSH remote; HTTPS git fails here
```
